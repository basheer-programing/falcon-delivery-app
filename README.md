## 1. مقدمة عن المشروع

**Falcon Delivery** هو مساعد ذكي (Chatbot) مبني على إطار عمل **Rasa**، مصمم لتسهيل عملية طلب الطعام والتوصيل من خلال واجهة محادثة طبيعية باللغة العربية. يهدف المشروع إلى تقديم حل متكامل يربط العملاء بالمطاعم والسائقين، مع ميزات متقدمة مثل:

- 🔍 البحث عن المنتجات حسب الاسم أو الميزانية أو المتجر
- 🛒 إدارة سلة الطلب
- 📦 تأكيد الطلب مع توليد رقم تتبع
- 🚚 تتبع الطلب لحظياً
- ⭐ تقييم الخدمة
- 📝 تقديم شكاوى
- 🧠 خوارزمية دمج الطلبات الذكية (Batch Delivery)

---

## 2. الأهداف الرئيسية

1. **تسهيل تجربة العميل**: طلب الطعام عبر محادثة طبيعية بدلاً من التنقل في واجهات معقدة.
2. **دمج ذكي للطلبات**: تقليل عدد الرحلات وزيادة كفاءة السائقين.
3. **دعم الدفع المحلي**: الدفع النقدي عند الاستلام و ShamCash.
4. **تتبع لحظي**: معرفة موقع السائق وحالة الطلب.
5. **تحليل الأداء**: تقديم تقارير للمديرين والمتاجر.
6. **تعليمي أكاديمي**: تطبيق عملي لمفاهيم هندسة البرمجيات، الذكاء الاصطناعي، وتحليل النظم.

## 5. شرح ملفات Rasa بالتفصيل

### 5.1 ملف `nlu.yml`

**الوظيفة**: يحتوي على بيانات تدريب نموذج فهم اللغة الطبيعية (NLU). يحدد:
- **النيات (Intents)**: ما يريد المستخدم فعله (طلب، تتبع، إلغاء، إلخ).
- **الكيانات (Entities)**: المعلومات المهمة في النص (منتج، ميزانية، متجر، رقم طلب).
- **المرادفات (Synonyms)**: توحيد المصطلحات المختلفة لنفس المعنى.
- **التعبيرات النمطية (Regex)**: لاستخراج الأرقام والمعرفات.

**مثال على نية**:

```yaml
- intent: order_request
  examples: |
    - أريد [بيتزا](product)
    - بدي [شاورما](product)
    - جوعان بدي [وجبة](product)
```

**مثال على كيان**:

```yaml
entities:
  - product
  - budget
  - store
```

**مثال على مرادف**:

```yaml
- synonym: "بيتزا"
  examples: |
    - pizza
    - بيتزا عادي
```

---

### 5.2 ملف `domain.yml`

**الوظيفة**: يحدد نطاق المساعد بالكامل:
- **النيات (Intents)**: قائمة بكل ما يمكن للمستخدم قوله.
- **الكيانات (Entities)**: نفسها من `nlu.yml` ولكن تُستخدم للتحقق.
- **الفتحات (Slots)**: تخزين البيانات المستخرجة من المستخدم.
- **النماذج (Forms)**: لتجميع البيانات المفقودة خطوة بخطوة.
- **الردود (Responses)**: الرسائل النصية والأزرار التي يرسلها المساعد.
- **الأفعال (Actions)**: الأفعال المخصصة التي ينفذها الخادم.

**مثال على فتحة (Slot)**:

```yaml
slots:
  product:
    type: text
    influence_conversation: true
    mappings:
      - type: from_entity
        entity: product
```

**مثال على رد (Response)**:

```yaml
responses:
  utter_greet:
    - text: |
        مرحباً بك في {Falcon Delivery}! 🦅
        كيف يمكنني مساعدتك اليوم؟
```

**مثال على نموذج (Form)**:

```yaml
forms:
  order_form:
    required_slots:
      - product
      - budget
      - store
      - delivery_time
```

### 5.3 ملف `config.yml`

**الوظيفة**: يحدد إعدادات التدريب وخطوط المعالجة (Pipeline) والسياسات (Policies).

**خط المعالجة (Pipeline)** – تسلسل المكونات التي تحول النص إلى تمثيل رقمي:

```yaml
pipeline:
  - name: WhitespaceTokenizer          # تجزئة النص إلى كلمات
  - name: RegexFeaturizer              # استخراج الأنماط الثابتة
  - name: LexicalSyntacticFeaturizer   # تحليل السمات اللغوية
  - name: CountVectorsFeaturizer       # تحويل النص إلى متجهات (كلمات)
  - name: CountVectorsFeaturizer       # تحويل النص إلى متجهات (أحرف)
  - name: DIETClassifier               # تصنيف النية واستخراج الكيانات
  - name: EntitySynonymMapper          # مطابقة المرادفات
  - name: ResponseSelector             # اختيار الردود للأسئلة الشائعة
  - name: FallbackClassifier           # التعامل مع الحالات منخفضة الثقة
```

**السياسات (Policies)** – تحدد كيفية اتخاذ القرارات في الحوار:

```yaml
policies:
  - name: MemoizationPolicy            # حفظ الحوارات السابقة
  - name: RulePolicy                   # تطبيق القواعد الثابتة
  - name: TEDPolicy                    # تعلم الحوار العميق
  - name: UnexpecTEDIntentPolicy       # التعامل مع النيات غير المتوقعة
  - name: AugmentedMemoizationPolicy   # حفظ محسن للحوارات
```

### 5.6 ملف `actions/actions.py`

**الوظيفة**: يحتوي على تنفيذ الأفعال المخصصة (Custom Actions) المكتوبة بلغة Python. هذه الأفعال هي التي تنفذ منطق الأعمال الحقيقي للنظام.

**قائمة الأفعال المخصصة**:

| الفعل | الوظيفة |
|-------|---------|
| `action_search_products` | البحث عن المنتجات حسب الاسم أو الميزانية أو المتجر |
| `action_handle_budget` | معالجة الميزانية وعرض اقتراحات مناسبة |
| `action_add_to_cart` | إضافة منتج إلى سلة الطلب |
| `action_confirm_order_logic` | تأكيد الطلب وتنفيذ خوارزمية الدمج الذكية |
| `action_track_order` | تتبع الطلب وعرض حالته وموقع السائق |
| `action_payment_process` | معالجة الدفع (نقدي أو ShamCash) |
| `action_validate_payment` | التحقق من صحة الدفع |
| `action_show_recommendations` | عرض توصيات ذكية |
| `action_show_order_history` | عرض تاريخ الطلبات السابقة |
| `action_submit_rating` | معالجة التقييم |
| `action_handle_complaint` | معالجة الشكاوى |
| `action_reset_slots` | إعادة تعيين جميع الفتحات |
| `action_show_local_offers` | عرض العروض حسب المنطقة |
| `action_show_product_details` | عرض تفاصيل منتج محدد |
| `action_contact_support` | عرض معلومات التواصل مع الدعم |

**مثال على تنفيذ فعل**:

```python
class ActionSearchProducts(Action):
    def name(self) -> Text:
        return "action_search_products"

    def run(self, dispatcher: CollectingDispatcher,
            tracker: Tracker,
            domain: Dict[Text, Any]) -> List[Dict[Text, Any]]:
        
        product = tracker.get_slot("product")
        # منطق البحث عن المنتج في قاعدة البيانات
        dispatcher.utter_message(text=f"🔍 جارٍ البحث عن {product}...")
        return []
```

### 7.3 خوارزمية دمج الطلبات

أهم فعل هو `action_confirm_order_logic`، الذي ينفذ خوارزمية دمج الطلبات الذكية:

1. **البحث عن سائقين متاحين** ضمن نطاق 10 كم.
2. **إذا لم يوجد سائق متاح**: البحث عن سائقين لديهم طلبات حالية ويمكن دمج الطلب الجديد معها.
3. **شروط الدمج**:
   - ألا يتجاوز عدد الطلبات لكل سائق 3.
   - ألا يزيد الفارق الزمني بين أقدم وأحدث طلب عن 10 دقائق.
   - ألا تزيد المسافة بين المطاعم عن 1 كم.
   - ألا تزيد المسافة بين العملاء عن 5 كم.
4. **إعادة حساب المسار الأمثل** باستخدام خوارزمية أقرب جار (Nearest Neighbor).
5. **إذا لم يوجد سائق مناسب**: وضع الطلب في قائمة انتظار وإعادة المحاولة كل 30 ثانية.

## 8. خوارزمية دمج الطلبات الذكية

### 8.1 صياغة المشكلة

لدينا:
- مجموعة من الطلبات الجديدة التي تحتاج إلى توصيل.
- مجموعة من السائقين المتاحين أو المشغولين جزئياً.
- قيود: المسافة، الزمن، الحد الأقصى للطلبات.

### 8.2 الخوارزمية

```
1. لكل طلب جديد:
   a. البحث عن سائقين متاحين ضمن 10 كم.
   b. إذا وجد: إسناد الطلب لأقرب سائق.
   c. إذا لم يوجد:
      - البحث عن سائقين لديهم طلبات حالية (1 أو 2 طلب).
      - لكل سائق من هؤلاء، التحقق من شروط الدمج:
        * عدد الطلبات < 3
        * الفارق الزمني ≤ 10 دقائق
        * المسافة بين المطاعم ≤ 1 كم
        * المسافة بين العملاء ≤ 5 كم
      - إذا تحققت الشروط: إضافة الطلب إلى مجموعة السائق.
      - إعادة حساب المسار الأمثل.
   d. إذا لم يوجد سائق مناسب: وضع الطلب في قائمة الانتظار.
2. إعادة المحاولة على طلبات قائمة الانتظار كل 30 ثانية.
```

### 8.3 حساب المسار الأمثل (Nearest Neighbor)

```
1. ابدأ من موقع السائق الحالي.
2. كرر حتى زيارة جميع النقاط:
   a. اختر أقرب نقطة غير مزارة (مع قيد: المطعم قبل العميل).
   b. أضفها إلى المسار.
   c. انتقل إلى هذه النقطة.
3. أعد مصفوفة النقاط بالترتيب.
```

### 8.4 حساب المسافة (Haversine)

```python
def calculate_distance(lat1, lng1, lat2, lng2):
    R = 6371  # نصف قطر الأرض
    phi1 = math.radians(lat1)
    phi2 = math.radians(lat2)
    dphi = math.radians(lat2 - lat1)
    dlambda = math.radians(lng2 - lng1)
    a = sin(dphi/2)**2 + cos(phi1) * cos(phi2) * sin(dlambda/2)**2
    c = 2 * atan2(sqrt(a), sqrt(1-a))
    return R * c
```

## 11. استكشاف الأخطاء وإصلاحها

### 11.1 خطأ: `ModuleNotFoundError: No module named 'pkg_resources'`

**الحل:**
```bash
pip install --upgrade setuptools
```

### 11.2 خطأ: `ImportError: cannot import name 'LegacyVersion' from 'packaging.version'`

**الحل:**
```bash
pip install packaging==20.9
```

### 11.3 خطأ: `No stories present. Just a Rasa NLU model will be trained.`

**الأسباب المحتملة:**
- ملف `stories.yml` غير موجود أو اسمه خطأ.
- يوجد خطأ في صياغة YAML.
- ذاكرة التخزين المؤقت تمنع القراءة.

**الحل:**
```bash
# حذف ذاكرة التخزين المؤقت
Remove-Item -Recurse -Force .rasa_cache -ErrorAction SilentlyContinue

# التحقق من اسم الملف
dir data\  # يجب أن يظهر stories.yml

# إعادة التدريب
rasa train
```

### 11.4 خطأ: `Tried to set non existent slot 'cart'`

**الحل:**
أضف الفتحة `cart` في ملف `domain.yml`:

```yaml
slots:
  cart:
    type: list
    influence_conversation: false
    mappings:
      - type: custom
        action: ignore
```

### 11.5 خطأ: `YamlSyntaxException` أو `YamlValidationException`

**الأسباب:**
- استخدام علامات تبويب بدلاً من مسافات (استخدم مسافتين).
- وجود أحرف خاصة غير مدعومة (مثل `║`, `═`, `█`).
- تكرار المفاتيح (مثل `dense_dimension`).

**الحل:**
استخدم أداة التحقق: https://yamlchecker.com/

### 11.6 خطأ: خادم الأفعال لا يتصل

**الحل:**
```bash
# التحقق من أن خادم الأفعال يعمل
curl http://localhost:5055/status

# إعادة تشغيل خادم الأفعال مع تفعيل التصحيح
rasa run actions --debug --port 5055
```
